# 微信小程序 M2 实现记录

日期：2026-09-23。范围：从相册导入视频、选择封面时刻并导出本地 JPEG。未实现 Motion Photo 封装、相册保存、片段裁剪、时间轴缩略图和渐变；这些分别留给 M3/M4。

## 已接入

- 使用 `wx.chooseMedia` 选择本机视频；读取视频信息，并从所选文件头检查 MP4 `ftyp` 标识。
- 在已实现的视频页中保留原有导航、隐私提示、说明文案与底部固定操作栏。已选状态按 Android 运行截图的紧凑更换视频卡、视频画面预览、封面滑块、加载/错误和输出状态补齐。
- 使用 `wx.createVideoDecoder` 定位封面时刻、取得 RGBA 帧；通过 2D Canvas 处理方向元数据，并用 JPEG 格式导出临时本地文件。
- 封面预览直接使用刚导出的 JPEG；最终结果复用同一文件，避免预览帧和输出帧不一致。解码日志包含目标秒数、原始 PTS/DTS、输出尺寸。

## 当前限制与待验证

- 设备上是否能处理具体视频取决于微信解码器；首批目标样本为 H.264 MP4。容器检查只能确认 MP4 `ftyp`，不判断 H.264 编码，实际解码失败会显示错误。
- 已在微信开发者工具 2.02.2608070 中选取本机 H.264 MP4，读取视频信息并显示视频预览；画布初始化后，逐帧解码调用返回“开发者工具暂时不支持此 API 调试，请使用真机进行开发”。因此开发者工具不能完成此流程的帧提取/JPEG 验证，必须在真机继续验证。
- `pkPts`/`pkDts` 在微信类型定义中仅标注为原始 PTS/DTS，没有声明时间单位。代码记录原始值，不臆测单位；要完成“实际帧时间与目标时间的偏差”验收，需用目标 Android/iOS 微信版本校准并记录。
- 当前 JPEG 是小程序临时文件；写入相册、保留 JPEG 尾部附加数据和 Samsung Motion Photo 校验均属于 M3。
- 当前设置帧像素上限为 10,000,000。超出时会提示缩小视频后重试，以控制 Canvas 内存占用。
- 尚未在微信开发者工具、Android 微信真机或 iOS 微信真机执行完整 M2 媒体链路；因此本记录表示代码已实现，不代表 M2 验收通过。

## 微信开发者工具基础加载记录

2026-09-23 使用微信开发者工具 2.02.2608070，在 GUI 中以游客模式打开仓库项目。IDE 日志显示读取了小程序主包、页面配置和 WXSS，`pageframe` 报告用户代码加载完成，随后 `webview page ready`。这确认项目基础加载已跑通，但没有选择视频，也没有验证解码、选帧或 JPEG 导出。

CLI 的 `open --project` 接口仍对占位 AppID `touristappid` 返回错误码 10；`auto --project <仓库路径> --trust-project` 可识别该游客 AppID 并初始化自动化。CLI 的打开错误与 GUI 中已打开项目是两条不同路径，不代表源码编译失败。

仓库当前没有视频样本。完整 M2 验证仍需在开发者工具中选取 H.264 MP4，确认时长/尺寸、拖动选帧、生成并预览 JPEG，再在 Android 与 iOS 微信真机重复验证。

## 真机验证步骤

1. 用开发者工具“预览”在 Android 微信真机打开小程序，并把 H.264 MP4 测试视频放入手机相册。
2. 从视频生成页选择该视频，确认时长/画幅信息正确且画面可播放；拖动滑块到不同时间点，等待封面预览更新。
3. 点“生成封面 JPEG”，确认页面结果图可见，点结果图可调用微信图片预览。
4. 收集真机调试日志中的目标秒数、原始 PTS/DTS、JPEG 像素尺寸；记录样本文件时长、尺寸、大小与解码结果。
5. 在 Android 微信和 iOS 微信各重复一次，比较指定时刻的预览 JPEG 与目标视频帧，并确认页面状态/排版与 Android 基准截图一致。

完成上述真机记录后，再将媒体能力标记为 M2 验收完成。
